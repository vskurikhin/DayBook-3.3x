## SENIOR ARCHITECT GATE
Перед началом реализации найди итоговый verdict в: .ai/senior-architect/review-round-3-spot-check.md <- это последний документ от Senior Architect
Если verdict: APPROVED можно переходить к реализации.
Если verdict: CHANGES_REQUIRED или: REJECTED НЕ изменяй production code.
В этом случае остановись и сообщи: ARCHITECTURE_NOT_APPROVED с кратким описанием причин.
Не пытайся самостоятельно исправить архитектуру.

## ПОРЯДОК РЕАЛИЗАЦИИ
Проверь какие задачи уже реализованы.
Не реализовывай в порядке TASK-001 → TASK-NNN вслепую одним большим изменением.
Работай последовательно по dependency graph, указанному Architect.
Перед каждой задачей:
1. Прочитай соответствующий TASK.
2. Проверь его зависимости.
3. Изучи существующий код.
4. Реализуй только требуемый scope.
5. Добавь/измени тесты согласно acceptance criteria.
6. Выполни форматирование.
7. Запусти релевантные тесты.
8. Проверь git diff.
9. Только после этого переходи к следующей задаче.

Если зависимости TASK не позволяют безопасно выполнить задачу — остановись и сообщи BLOCKED.
Не меняй public API без необходимости.

## КОД
Следуй существующим conventions проекта.
Обязательно:
- gofmt;
- idiomatic Go;
- минимальный diff;
- не делать unrelated refactoring;
- не переименовывать API без необходимости;
- не менять behavior вне scope;
- не добавлять зависимости без необходимости;
- не скрывать ошибки;
- не использовать panic там, где существующая архитектура предполагает
  нормальную обработку ошибки.

## ТЕСТИРОВАНИЕ
После каждой значимой задачи запускай релевантные тесты.
Минимум после завершения:
```bash
    make lint
```
Затем:
```bash
    go test . -run '<TestCase-1|TestCase-2|TestCase-3|...>'
```
Также:
```bash
    go test -race . -run '<TestCase-1|TestCase-2|TestCase-3|...>'
```
если проект и тесты позволяют такой запуск.
Не объявляй задачу выполненной только потому, что:
```bash
    go test . ./pkg/..
```
прошёл. Учти что тест может выполняться дольше чем 360s
Если, в тестировании задачи, используешь -count, то не больше 3.

### После завершения этапа или всех задач
Убедись что код соответствует:
```bash
    make lint
```
Запусти общий тест-сьют:
```bash
    make test
```
Также:
```bash
    make test-race
```

## GIT DIFF REVIEW
Перед завершением проверь:
```bash
    git diff --stat
    git diff
```
Убедись, что:
- нет случайных изменений;
- нет временных файлов;
- нет debug code;
- нет лишних зависимостей;
- нет изменений вне scope;
- НЕ коммить в текущую ветку и ветку main.
