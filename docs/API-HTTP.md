# Справочник HTTP API KV-сервиса

HTTP API KV-сервиса — внешний интерфейс реплицированного хранилища
«ключ–значение», работающего на консенсусе Raft. Сервис принимает
HTTP-запросы, выполняет операции чтения и записи через консенсус-модуль
и возвращает результаты в JSON. Справочник описывает все маршруты,
форматы запросов и ответов (типы пакета pkg/api), модель статусов
RespStatus, транспортные коды, гарантии доставки и поведение штатного
Go-клиента (пакет pkg/kvclient).

Базовый адрес: узел слушает HTTP-адрес, заданный флагом `-http-addr`
исполняемого файла raftkv. В демонстрационном стенде `make start-raft`
три узла слушают порты 8881–8883:
http://localhost:8881, http://localhost:8882, http://localhost:8883.
Запрос можно отправить любому узлу, но операцию подтверждает только
лидер (см. StatusNotLeader ниже).

## Маршруты

Маршруты регистрируются в маршрутизаторе ServeMux стандартной
библиотеки (шаблоны «метод + путь», Go 1.22+).

| Маршрут                  | Назначение          |  Запрос        | Ответ          |
|--------------------------|---------------------|----------------|----------------|
| `GET /verifyleader/`     | проверка лидерства  |  без тела      | StatusResponse |
| `GET /weak-get/{key...}` | слабое чтение       |  ключ в пути   | GetResponse    |
| `POST /cas/`             | условная запись     |  CASRequest    | CASResponse    |
| `POST /delete/`          | удаление            |  DeleteRequest | DeleteResponse |
| `POST /get/`             | консенсусное чтение |  GetRequest    | GetResponse    |
| `POST /put/`             | запись              |  PutRequest    | PutResponse    |

## Общие правила

- Тело POST-запроса — JSON с обязательным заголовком
  `Content-Type: application/json`. Разбор выполняет readRequestJSON
  отсутствие или другой тип заголовка, некорректный JSON, 
  несоответствие типа поля и неизвестные поля тела (DisallowUnknownFields)
  — ошибка разбора, ответ 400. GET-маршруты тела не разбирают,
  заголовок для них не требуется.
- Ответ с результатом операции всегда возвращается с кодом HTTP 200
  и JSON-телом; итог операции передаётся полем RespStatus, а не
  HTTP-кодом. Причина: у состояний «не лидер» или «не удалось
  зафиксировать команду» нет подходящих аналогов среди стандартных
  HTTP-кодов, поэтому в каждом ответе присутствует собственный
  статус ResponseStatus.
- Ответы GET-маршрутов /verifyleader/ и /weak-get/ сопровождаются
  заголовком `Cache-Control: no-store`: вердикт о лидерстве 
  и прочитанное значение актуальны только на  момент подтверждения лидерства,
  хранение ответа кешами запрещено.
- Сериализация ответов — json.Marshal; ошибка сериализации — ответ 500.

## Статусы RespStatus

Тип ResponseStatus объявлен в pkg/api/api.go.

| Значение | Имя                                 | Семантика                                                                                                                                                                                                                                  |
|----------|-------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 0        | StatusInvalid / "invalid"           | несовместимый ответ операции                                                                                                                                                                                                               |
| 1        | StatusOK / "OK"                     | операция выполнена                                                                                                                                                                                                                         |
| 2        | StatusNotLeader / "NotLeader"       | операция не подтверждена данным узлом: узел не лидер, либо истёк тайм-аут постановки команды в очередь консенсус-модуля, либо лидерство утрачено/передаётся, либо узел останавливается; клиенту следует повторить команду на другом адресе |
| 3        | StatusFailedCommit / "FailedCommit" | обработчиками не возвращается; Go-клиент трактует как «фиксация не удалась, повторить»                                                                                                                                                     |

Пояснения к таблице:

- StatusNotLeader возвращается на любую ошибку future
  консенсус-модуля, а не только на «узел не лидер»: ErrNotLeader
  — узел не лидер; contract.ErrEnqueueTimeout — истёк тайм-аут 
  постановки команды в очередь applyCh;
  ErrLeadershipTransferInProgress — идёт передача лидерства; contract.ErrRaftShutdown
  — узел останавливается; ErrLeadershipLost — лидерство утрачено;
  ErrTooManyUncommittedEntries — превышен  лимит незафиксированного хвоста журнала.
- StatusInvalid возвращается, когда ответ future не приводится к типу
  команды, — нештатное внутреннее несоответствие; штатный Go-клиент в этой ситуации
  аварийно завершается (раздел «Поведение Go-клиента»).
- StatusFailedCommit — клиентский резервный случай: обработчиками
  HTTP-маршрутов не возвращается (в pkg/kvservice значение не
  используется), предназначен клиентской стороне — Go-клиент трактует
  его как «фиксация не удалась, повторить».

## Транспортные коды

| Код | Когда возвращается                                                                                                                                                          |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 400 | заголовок Content-Type отсутствует или не application/json; тело не является корректным JSON; тип поля не совпадает; тело содержит неизвестные поля (DisallowUnknownFields) |
| 404 | маршрут не найден                                                                                                                                                           |
| 405 | HTTP-метод не совпал с шаблоном маршрута                                                                                                                                    |
| 500 | ошибка сериализации ответа (json.Marshal)                                                                                                                                   |

Отмена контекста запроса. Если клиент отменяет контекст запроса
(разрывает соединение) до завершения операции, обработчик
завершается, не записывая тело ответа: ожидание построено на select
по req.Context().Done().
Это верно для маршрута `GET /weak-get/{key...}` и всех POST-маршрутов.

## Гарантии и повторы

- Доставка команды — не менее одного раза: сервис не гарантирует
  однократное выполнение, повторно отправленная команда выполняется
  повторно. Дедупликации команд по идентификатору запроса в сервисе
  нет.
- StatusNotLeader не означает, что команда не будет зафиксирована:
  запись может уже находиться в журнале лидера и зафиксироваться позже.
  Уже добавленную в журнал запись не отменяет только потеря лидерства
  (ErrLeadershipLost — future получает ошибку, но запись остаётся в журнале).
  При contract.ErrEnqueueTimeout и ErrTooManyUncommittedEntries команда
  в журнал не попадает (возврат из ветки таймера, отправка в applyCh
  не состоялась; ответ future до добавления записи); при ErrNotLeader и
  contract.ErrRaftShutdown — тоже.
  Все эти ошибки future обработчики отражают одним статусом
  StatusNotLeader (ErrNotLeader, contract.ErrEnqueueTimeout,
  ErrLeadershipTransferInProgress, contract.ErrRaftShutdown,
  ErrLeadershipLost, ErrTooManyUncommittedEntries).
- Штатный Go-клиент на StatusNotLeader переключает адрес и повторяет
  ту же команду.
- Последствия повторов:
  - PUT — повторная запись того же значения (формально операция не
    идемпотентна, если значение менялось между повторами);
  - CAS — повтор выполняется заново против текущего состояния
    (PrevValue может отличаться, повторный CAS может не найти прежнее
    значение);
  - DELETE — повтор вернёт KeyFound=false, если удаление уже
    зафиксировано.

## Маршруты подробнее

### `GET /verifyleader/` — проверка лидерства

- Обработчик: handleVerifyLeader — pkg/kvservice/kvservice.go.
- Запрос: без тела и параметров.
- Ответ: StatusResponse {RespStatus} (pkg/api/api.go):
  StatusOK — узел подтвердил лидерство, StatusNotLeader — не
  подтвердил.
- Заголовок ответа: `Cache-Control: no-store` (kvservice.go) —
  вердикт о лидерстве актуален только на момент кворумного
  подтверждения.
- Проверка выполняется без записи в журнал — механизм ReadIndex
  (раздел 8 статьи Raft): вызов VerifyLeader собирает кворумное
  подтверждение соседей по текущему состоянию.
- Маршрут `/verifyleader/` не проверяет отмену контекста запроса и не
  имеет тайм-аута (вызов VerifyLeader().Error() блокирующий).

### `GET /weak-get/{key...}` — слабое чтение

- Обработчик: handleWeakGet — pkg/kvservice/kvservice.go.
- Ключ передаётся суффиксом пути после префикса /weak-get/; шаблон
  {key...} захватывает весь остаток пути, в том числе несколько
  сегментов со слэшами: запрос /weak-get/a/b соответствует ключу
  "a/b".
- Запрос: без тела. Ответ: GetResponse {RespStatus, KeyFound, Value}.
- Заголовок ответа: `Cache-Control: no-store` (kvservice.go) —
  значение актуально только на момент подтверждения лидерства.
- Порядок работы: сначала подтверждение лидерства через VerifyLeader
  без записи в журнал, затем локальное чтение хранилища ds.Get.
  Ошибка подтверждения лидерства — StatusNotLeader;
  отсутствие ключа — StatusOK с KeyFound=false.
- Отмена контекста запроса — пустой ответ без тела.
- Экранирование ключа: клиент кодирует ключ функцией url.PathEscape
  (pkg/kvclient/kvclient.go); ключи "." и ".." экранируются
  вручную (%2E и %2E%2E), так как PathEscape не кодирует точку, а
  точечные сегменты пути переписываются маршрутизатором.

### Механика POST-маршрутов

Каждый POST-маршрут после разбора тела выполняет одни и те же шаги:

1. Из тела запроса формируется команда; она подаётся в raft Apply с
   аргументом _requestTimeout = 10с.
2. Эти 10 секунд — тайм-аут постановки команды в очередь
   консенсус-модуля (applyCh): если команда не принята в очередь за
   это время, Apply возвращает contract.ErrEnqueueTimeout.
   Это тайм-аут постановки, а не тайм-аут фиксации: время записи 
   в журнал и применения команды этим сроком не ограничено.
3. Ожидание фиксации ограничено только отменой контекста запроса:
   обработчик выбирает между завершением future и req.Context().Done().
4. Любая ошибка future (перечень — раздел «Гарантии и повторы»)
   возвращает StatusNotLeader.
5. Ответ future, не приводимый к типу команды, возвращает StatusInvalid.

### `POST /cas/` — условная запись

- Обработчик: handleCAS — pkg/kvservice/kvservice.go.
- Запрос: CASRequest (pkg/api/api.go):

  | Поле         | Тип    | Смысл                            |
  |--------------|--------|----------------------------------|
  | Key          | string | ключ                             |
  | CompareValue | string | ожидаемое текущее значение ключа |
  | Value        | string | записываемое значение            |

- Ответ: CASResponse (pkg/api/api.go):

  | Поле       | Тип                    | Смысл                           |
  |------------|------------------------|---------------------------------|
  | RespStatus | ResponseStatus (число) | статус операции                 |
  | KeyFound   | bool                   | существовал ли ключ до операции |
  | PrevValue  | string                 | значение ключа до операции      |

- Семантика: если текущее значение ключа Key равно CompareValue,
  записывается Value; KeyFound — существовал ли ключ, PrevValue — его
  значение до операции. Команда фиксируется через журнал
  (консенсус).

### `POST /delete/` — удаление

- Обработчик: handleDelete — pkg/kvservice/kvservice.go.
- Запрос: DeleteRequest (pkg/api/api.go)
- Ответ: DeleteResponse (pkg/api/api.go):

  | Поле       | Тип                    | Смысл                           |
  |------------|------------------------|---------------------------------|
  | RespStatus | ResponseStatus (число) | статус операции                 |
  | KeyFound   | bool                   | существовал ли ключ до операции |
  | PrevValue  | string                 | значение ключа до операции      |

- Семантика: удаляет ключ; KeyFound и PrevValue описывают состояние
  до удаления. Команда фиксируется через журнал (консенсус).

### `POST /get/` — консенсусное чтение

- Обработчик: handleGet — pkg/kvservice/kvservice.go.
- Запрос: GetRequest (pkg/api/api.go):
- Ответ: GetResponse (pkg/api/api.go):

  | Поле       | Тип                    | Смысл              |
  |------------|------------------------|--------------------|
  | RespStatus | ResponseStatus (число) | статус операции    |
  | KeyFound   | bool                   | существует ли ключ |
  | Value      | string                 | значение ключа     |

- Семантика: чтение через журнал — команда проходит консенсус и
  применяется к машине состояний, поэтому результат согласован с
  другими операциями. В отличие от слабого чтения
  `GET /weak-get/{key...}` значение подтверждается кворумом.

### `POST /put/` — запись

- Обработчик: handlePut — pkg/kvservice/kvservice.go.
- Запрос: PutRequest (pkg/api/api.go):

  | Поле  | Тип    | Смысл                 |
  |-------|--------|-----------------------|
  | Key   | string | ключ                  |
  | Value | string | записываемое значение |

- Ответ: PutResponse (pkg/api/api.go):

  | Поле       | Тип                    | Смысл                           |
  |------------|------------------------|---------------------------------|
  | RespStatus | ResponseStatus (число) | статус операции                 |
  | KeyFound   | bool                   | существовал ли ключ до операции |
  | PrevValue  | string                 | значение ключа до операции      |

- Семантика: сохраняет Value по ключу Key; KeyFound и PrevValue
  описывают состояние до записи. Команда фиксируется через журнал
  (консенсус).

## Поведение Go-клиента (pkg/kvclient)

Штатный Go-клиент пакета pkg/kvclient работает со списком адресов
узлов и повторяет операцию до подтверждения:

- assumedLeader — индекс адреса узла, который клиент в данный момент
  предполагает лидером (pkg/kvclient/kvclient.go); индекс читается
  и изменяется атомарно.
- При StatusNotLeader или ошибке запроса (в том числе тайм-ауте)
  клиент переключается на следующий адрес списка и повторяет ту же
  команду (kvclient.go — POST-маршруты; — слабое чтение; проверка лидерства).
- Ответы 405 и 404 в GET-путях — детерминированные ошибки: метод и
  маршрут одинаковы для всех узлов, переключение адреса бессмысленно.
- Тайм-аут одного HTTP-запроса — 500 мс по умолчанию; настраивается
  конструктором NewWithTimeout.
- StatusFailedCommit клиент трактует как «фиксация не удалась,
  повторить» и возвращает ошибку.
- Статус, отличный от StatusOK, StatusNotLeader, StatusFailedCommit
  (в частности StatusInvalid), приводит штатного Go-клиента к панике
  panic("unreachable") — процесс вызывающей стороны аварийно завершается;
  сервер способен вернуть StatusInvalid.
- Ключи слабого чтения кодируются функцией url.PathEscape, включая
  ключи, содержащие точку (специальные случаи "." и ".." — вручную.

## Примеры запросов

Примеры для стенда `make start-raft` в примерах узлы 8881–8883; 
допущение: лидером считается узел 8881.
Числовое значение RespStatus — в
комментарии к каждому вызову.

```bash
# Проверка лидерства — ответ узла-лидера
curl -s http://localhost:8881/verifyleader/
# {"RespStatus":1}

# Проверка лидерства — ответ ведомого узла
curl -s http://localhost:8882/verifyleader/
# {"RespStatus":2}

# Слабое чтение значения ключа my-key (ключ — суффикс пути)
curl -s http://localhost:8881/weak-get/my-key
# {"RespStatus":1,"KeyFound":true,"Value":"v-1"}

# Запись пары my-key=v-1 (ключа ещё нет, поэтому KeyFound=false)
curl -s -X POST http://localhost:8881/put/ \
  -H 'Content-Type: application/json' \
  -d '{"Key":"my-key","Value":"v-1"}'
# {"RespStatus":1,"KeyFound":false,"PrevValue":""}

# Консенсусное чтение
curl -s -X POST http://localhost:8881/get/ \
  -H 'Content-Type: application/json' \
  -d '{"Key":"my-key"}'
# {"RespStatus":1,"KeyFound":true,"Value":"v-1"}

# Условная запись: текущее значение v-1 заменяется на v-2
curl -s -X POST http://localhost:8881/cas/ \
  -H 'Content-Type: application/json' \
  -d '{"Key":"my-key","CompareValue":"v-1","Value":"v-2"}'
# {"RespStatus":1,"KeyFound":true,"PrevValue":"v-1"}

# Удаление ключа
curl -s -X POST http://localhost:8881/delete/ \
  -H 'Content-Type: application/json' \
  -d '{"Key":"my-key"}'
# {"RespStatus":1,"KeyFound":true,"PrevValue":"v-2"}

# Запрос записи на ведомом узле: операция не подтверждена данным
# узлом, клиенту следует повторить команду на другом адресе
curl -s -X POST http://localhost:8883/put/ \
  -H 'Content-Type: application/json' \
  -d '{"Key":"my-key","Value":"v-3"}'
# {"RespStatus":2,"KeyFound":false,"PrevValue":""}
```
