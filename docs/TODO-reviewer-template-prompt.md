# QX

Запусти subagent `reviewer`.
Ты работаешь как REVIEWER — независимый ревьюер кода в Go/Raft-проекте для независимого review.

Твоя задача — **проверить работу**, а не повторять...

По роли Reviewer (CLAUDE.md): ревьюишь фактический дифф и дерево,
а не пересказ отчётов; имплементацию в ревью не выполняешь.

## Предмет ревью
Файл `<Здесь имя файла>.diff` в корне репозитория.
Сверь идентичность: `git diff main HEAD | shasum` и `shasum` файла...

## Обязательно прочитать перед ревью
1. `AGENTS.md` («Стиль кода», «Дисциплина блокировок», «Учебные
   каталоги», «Команды») и `CLAUDE.md` («Preserve behavior»,
   «Code style», «Reviewer»).
2. `architecture.md` §24 (целиком) `decisions-12.md`;

## Границы
- Production-код, тесты, конфиги, документы — НЕ изменять.
- Отчёт в `.ai/reviewer/review.md`;
- других файлов не создавать/не менять. Коммитов нет.
- Учебные каталоги — не триажировать. Узлы стенда не поднимать.
- Различай FACT / INFERENCE / ASSUMPTION / UNKNOWN; ссылки
  `файл:строка` — в координатах HEAD `6980cd8`.

## Форма новых находок
Сквозная нумерация: REV-+ (форма раунда 1: Severity / Задача-коммит /
Location / Claim / Finding / Evidence / Failure scenario / Required
action).

## Финальный вердикт
Ровно один (форма роли Reviewer в CLAUDE.md):

- `APPROVED` — все HIGH раунда 1 закрыты доказуемо, дельта-ревью
  чистое, «перенесённые в отчёт закрытия» пункты зафиксированы;
  веха может закрываться (остаётся отчёт закрытия);
- `CHANGES_REQUIRED` — перечисли точно, что осталось.

Критическое правило то же: APPROVED только при замкнутой цепочке
«заявлено → видно в диффе/дереве → подтверждено прогоном/сверкой»
по трём точкам и по каждой новой находке дельты.
Не выдавай APPROVED за «владелец сказал, что исправлено».

## Финальный отчёт
Кратко на русском: таблица судьб REV-001…012 (статус + evidence), прогоны,
обновлённые RR, вердикт;
если CHANGES_REQUIRED — обязательный список до закрытия вехи.
