# Флаги командной строки

## Назначение документа

Справочник флагов командной строки двух программ репозитория: узла
`raftkv` и генератора нагрузки `loadkv`. Для каждого флага приведены имя,
умолчание, единица и границы допустимых значений. Недопустимые значения
обнаруживаются при запуске по стратегии немедленного отказа: процесс
завершается до начала работы, а сообщение выводит флаг, фактическое
значение и требование.

В документе описываются только флаги командной строки. Программные
интерфейсы (HTTP-интерфейс KV-сервиса, API пакета `raft`) и переменные
окружения описываются отдельными документами.

### Временные параметры

Проверяются при запуске функцией `raft.ValidateTiming` (раздел
«Инварианты временных параметров»); значения задаются целым числом
миллисекунд.

| Флаг                    | Умолчание | Единица  | Границы                                                                                                                                                                      |
|-------------------------|-----------|----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `-apply-batch-interval` | 50 мс     | duration | [1 мс; 5000 мс], целые мс, ≤ reelection-timeout                                                                                                                              |
| `-heartbeat-timeout`    | 33 мс     | duration | [5 мс; 100 мс], целые мс; 100 = ⌊400/4⌋                                                                                                                                      |
| `-reelection-timeout`   | 430 мс    | duration | [200 мс; 30 000 мс], целые мс, ≥ 10·heartbeat-timeout, > 2 × raft.TCPRPCTimeout = 400 мс (окно проверки кворума фиксировано и флагом `-tcp-rpc-timeout` не масштабируется)   |
| `-ticker-timeout`       | 20 мс     | duration | [1 мс; 1000 мс], целые мс, ≤ reelection-timeout/10                                                                                                                           |

- `-apply-batch-interval` — интервал, с которым цикл лидера проверяет
  необходимость применения зафиксированных записей к машине состояний;
  накопленные за интервал уведомления канала фиксации объединяются в
  один пакет.
- `-heartbeat-timeout` — период пульса лидера. Верхняя граница 100 мс
  выводится из фиксированного тайм-аута проверки кворума 400 мс: в окне
  проверки лидер обязан успеть не менее четырёх раз связаться с
  соседями, целочисленное округление вниз даёт ⌊400/4⌋ = 100 мс
  (`raft.go`, `MaxHeartbeatTimeout`).
- `-reelection-timeout` — опорная длительность для расчёта тайм‑аута выборов.  
  Фактическое значение выбирается случайно из диапазона `[reelection-timeout; 2·reelection-timeout)`.  
  Тем же временным окном ограничивается подавление предварительного голосования (pre‑vote) у получателя запроса.
  Опорная длительность должна строго превышать фиксированное окно проверки кворума:  
  `2 × raft.TCPRPCTimeout = 400 мс`.  
  Это окно является константой компиляции и не зависит от флага `-tcp-rpc-timeout`.
- `-ticker-timeout` — такт опроса таймера выборов; задаёт ошибку
  квантования тайм-аута выборов.

### RPC

| Флаг                        | Умолчание                              | Единица  | Границы                                                                                                                   |
|-----------------------------|----------------------------------------|----------|---------------------------------------------------------------------------------------------------------------------------|
| `-tcp-connect-timeout`      | 165 мс (raft.ConnectionTCPRPCTimeout)  | duration | > 0, целые мс; ≤ `-tcp-rpc-timeout`; вместе с ним ≤ 400 мс                                                                |
| `-tcp-rpc-timeout`          | 200 мс (raft.TCPRPCTimeout)            | duration | > 0, целые мс; с учётом: ≤ 400 мс − `-tcp-connect-timeout` (при умолчании `-tcp-connect-timeout` 165 мс — rpc ≤ 235 мс)   |
| `-install-snapshot-timeout` | 310 мс (raft.InstallSnapshotTimeout)   | duration | > 0, целые мс; ≥ `-tcp-rpc-timeout`                                                                                       |

`-tcp-rpc-timeout` — тайм-аут одного RPC-обмена запрос/ответ к соседу
в TCP-транспорте. Окно проверки кворума лидера фиксировано на 400 мс
(2 × raft.TCPRPCTimeout — константа компиляции) и НЕ масштабируется
этим флагом. Окно ожидания ответа потребителя (response) конструктивно
равно значению флага: отдельного флага у ответа нет.

`-tcp-connect-timeout` — тайм-аут только установки TCP-соединения
(DialTimeout). Эффективное окно одного RPC на новом соединении
складывается из установки соединения и дедлайна обмена: connect + rpc.
Инвариант требует connect ≤ rpc; суммарный запрет —
connect + rpc вместе не должны превышать фиксированное окно проверки
кворума 2 × raft.TCPRPCTimeout = 400 мс. Следствие для границ:
rpc ≤ 400 − connect (при умолчании `-tcp-connect-timeout` 165 мс —
rpc ≤ 235 мс).

`-install-snapshot-timeout` — база дедлайна передачи снимка: итоговый
дедлайн растёт с объёмом данных (блоки по 256 КиБ) на отправителе.
Флаг управляет обеими сторонами передачи: дедлайном отправителя и
окном ожидания ответа получателя (max с responseTimeout), включая
малые снимки < 256 КиБ. Инвариант требует базу не короче
`-tcp-rpc-timeout`.

### Снимки

| Флаг                   | Умолчание | Единица  | Границы |
|------------------------|-----------|----------|---------|
| `-snapshot-interval`   | 3 с       | duration | > 0     |
| `-snapshot-threshold`  | 1024      | записи   | ≥ 1     |

- `-snapshot-interval` — интервал проверки необходимости снимка: не
  реже чем раз в интервал узел проверяет порог снятия снимка.
- `-snapshot-threshold` — минимальное число записей журнала после
  последнего снимка, при котором создаётся новый снимок.

### Адреса и кластер

| Флаг         | Умолчание                              | Единица            | Границы                      |
|--------------|----------------------------------------|--------------------|------------------------------|
| `-data-dir`  | «» → `data/node-N` (cmd/main.go)       | путь               | —                            |
| `-http-addr` | `:8880`                                | адрес              | —                            |
| `-rpc-addr`  | `:9990`                                | адрес              | —                            |
| `-max-pool`  | 4 (DefaultMaxPool)                     | соединения         | ≥ 0; 0 заменяется на 4       |
| `-number`    | −1                                     | номер узла         | —                            |
| `-peers`     | «»                                     | `id=host:port,...` | разбор с немедленным отказом |

- `-data-dir` — директория постоянного хранилища узла (журнал и
  снимки); при пустом значении используется путь `data/node-N`, где N —
  значение флага `-number`.
- `-http-addr` — адрес HTTP-интерфейса узла.
- `-rpc-addr` — адрес RPC-сервера узла.
- `-max-pool` — максимальное число соединений в пуле на одного соседа.
  Отрицательное значение прерывает запуск; ноль заменяется на умолчание
  узла 4 (`DefaultMaxPool`, `cmd/main.go`). Собственное умолчание
  транспорта (2 соединения, `pkg/raft/transp`) при запуске узла не
  используется — замена нуля происходит до создания транспорта.
- `-number` — номер узла; передаётся в конфигурацию как идентификатор
  узла (ServerID) и участвует в пути данных по умолчанию.
- `-peers` — список соседей кластера: элементы `id=host:port` через
  запятую. Допускается префикс схемы `rpc://`; при отсутствии схемы
  адрес трактуется как RPC-адрес. Ошибка разбора любого элемента
  прерывает запуск.

### Трассировка

| Флаг                 | Умолчание   | Единица | Границы |
|----------------------|-------------|---------|---------|
| `-trace-cm-log-file` | «» = stderr | путь    | —       |
| `-trace-kv-log-file` | «» = stderr | путь    | —       |
| `-trace-log-level`   | 1           | уровень | —       |

- `-trace-cm-log-file` — файл журнала трассировки модуля консенсуса;
  пустое значение — стандартный поток ошибок.
- `-trace-kv-log-file` — файл журнала трассировки KV-сервиса; пустое
  значение — стандартный поток ошибок.
- `-trace-log-level` — порог отладочных сообщений трассировки для
  пакетов `raft` и `kvservice` (internal/config/config.go).
  Значение по умолчанию (в скомпилированной программе) равно 1.
  В конфигурации стенда используется иное значение (см. раздел
  «Профиль узла и профиль стенда»).

### Профилирование

| Флаг                      | Умолчание            | Единица | Границы |
|---------------------------|----------------------|---------|---------|
| `-pprof-addr`             | «пусто» == выключено | адрес   | —       |
| `-block-profile-rate`     | 0                    | события | —       |
| `-mutex-profile-fraction` | 0                    | события | —       |

- `-pprof-addr` — адрес отдельного HTTP-сервера профилирования; при
  пустом значении сервер не создаётся.
- `-block-profile-rate` — доля учитываемых событий блокировок;
  профилирование блокировок включается значением больше нуля
  (`runtime.SetBlockProfileRate`).
- `-mutex-profile-fraction` — доля учитываемых событий состязания за
  мьютекс; включается значением больше нуля
  (`runtime.SetMutexProfileFraction`).

## Инварианты временных параметров

Четыре временных флага проверяются при запуске функцией
`raft.ValidateTiming`: индивидуальные диапазоны,
целое число миллисекунд и межпараметрические требования.
Все нарушения собираются в одну ошибку (`errors.Join`)
и выдаются одним сообщением вида `invalid Raft timing flags: …`;
каждое нарушение называет флаг, фактическое значение и требование
(например: `heartbeat-timeout must be between 5ms and 100ms, got 110ms`).

| Параметр               | Диапазон                      | Межпараметрическое требование                                               |
|------------------------|-------------------------------|-----------------------------------------------------------------------------|
| `heartbeat-timeout`    | [5 мс; 100 мс], целые мс      | верхняя граница 100 мс = ⌊400/4⌋ — из фиксированных 400 мс проверки кворума |
| `ticker-timeout`       | [1 мс; 1000 мс], целые мс     | ≤ reelection-timeout/10                                                     |
| `reelection-timeout`   | [200 мс; 30 000 мс], целые мс | ≥ 10·heartbeat-timeout, > 2 × raft.TCPRPCTimeout = 400 мс                   |
| `apply-batch-interval` | [1 мс; 5000 мс], целые мс     | ≤ reelection-timeout                                                        |

Межпараметрические инварианты:

- `reelection-timeout` ≥ 10·heartbeat-timeout — за базу перевыборов
  лидер обязан успеть передать десять пульсов;
- `ticker-timeout` ≤ reelection-timeout/10 — такт не искажает тайм-аут
  выборов больше чем на десятую часть базы;
- `apply-batch-interval` ≤ reelection-timeout — пакетное применение не
  задерживает реакцию узла дольше базы перевыборов.

### Инварианты тайм-аутов TCP-транспорта

Три флага тайм-аутов TCP-транспорта проверяются при запуске чистыми
функциями `internal/config`: индивидуальные границы (положительное
значение, целое число миллисекунд) и жёсткие межпараметрические
инварианты. Все нарушения собираются в одну ошибку (`errors.Join`) и
выдаются сообщением вида `invalid TCP timeout flags: …`.

| Требование                                                                    | Пример нарушения                                                                                                 |
|-------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| `-tcp-connect-timeout` ≤ `-tcp-rpc-timeout`                                   | `-tcp-connect-timeout=230ms` при `-tcp-rpc-timeout=170ms` (230 > 170; сумма 400 ≤ 400 — единственное нарушение)  |
| `-install-snapshot-timeout` ≥ `-tcp-rpc-timeout`                              | `-install-snapshot-timeout=100ms` при `-tcp-rpc-timeout=200ms`                                                   |
| `-tcp-connect-timeout` + `-tcp-rpc-timeout` ≤ 2 × raft.TCPRPCTimeout = 400 мс | `-tcp-connect-timeout=165ms` при `-tcp-rpc-timeout=300ms` (сумма 465 > 400; выполнен — единственное нарушение)   |
| `-reelection-timeout` > 2 × raft.TCPRPCTimeout = 400 мс (от константы)        | `-reelection-timeout=400ms` (400 > 400 ложно; единственное нарушение)                                            |

Примеры:

- Валидная комбинация: `-heartbeat-timeout=40ms
  -reelection-timeout=430ms` — выполнено 430 ≥ 10·40 = 400 и 40 ≤ 100;
  при умолчаниях тикера 20 мс и пакетного применения 50 мс также
  выполнено 20 ≤ 430/10 = 43 и 50 ≤ 430.
- Невалидное значение: `-heartbeat-timeout=110ms` — выше верхней границы
  100 мс диапазона.
- Невалидная связка: `-heartbeat-timeout=45ms
  -reelection-timeout=440ms` — нарушено 440 ≥ 10·45 = 450.

На этапе запуска производится предварительная валидация конфигурации. Следующие значения считаются недопустимыми и приводят к немедленному отказу в инициализации:

- Значения флагов тайм‑аутов TCP‑транспорта, нарушающие индивидуальные границы или системные инварианты (проверяется каждый из трёх флагов).
- Значения, нарушающие инвариант опорной длительности для тайм‑аута перевыборов.
- Отрицательное значение параметра `-max-pool`.
- Неположительное значение параметра `-snapshot-interval` (≤ 0).
- Значение параметра `-snapshot-threshold` меньше 1.

Реализация механизма валидации: `internal/config/config.go`.

## Профиль узла и профиль стенда

Стенд `make start-raft` передаёт узлам значения, отличающиеся от
умолчаний бинарника (`Makefile:12–29`). Три набора чисел не следует
смешивать: умолчания бинарника, профиль стенда и умолчание транспорта.

| Параметр                                                                         | Умолчание флага узла | Значение стенда (Makefile) |
|----------------------------------------------------------------------------------|----------------------|----------------------------|
| Период пульса (`-heartbeat-timeout` / `HEARTBEAT_TIMEOUT`)                       | 33 мс                | 45 мс                      |
| База тайм-аута выборов (`-reelection-timeout` / `REELECTION_TIMEOUT`)            | 430 мс               | 500 мс                     |
| Такт тикера выборов (`-ticker-timeout` / `TICKER_TIMEOUT`)                       | 20 мс                | 20 мс                      |
| Интервал пакетного применения (`-apply-batch-interval` / `APPLY_BATCH_INTERVAL`) | 50 мс                | 50 мс                      |
| Уровень трассировки (`-trace-log-level` / `TRACE_LOG_LEVEL`)                     | 1                    | 0                          |

Профиль стенда валиден: 500 ≥ 10·45 = 450, 45 ≤ 100, 20 ≤ 500/10 = 50,
50 ≤ 500, 500 > 2 · raft.TCPRPCTimeout = 400 — от константы.

Запуск стенда на умолчаниях узла (полный набор переменных — чтобы
рецепт не зависел от текущих значений блока переменных `Makefile`):

```bash
make start-raft APPLY_BATCH_INTERVAL=50 HEARTBEAT_TIMEOUT=33 \
  REELECTION_TIMEOUT=430 TICKER_TIMEOUT=20
```

Подъём пульса ограничен сверху инвариантом
`reelection-timeout ≥ 10·heartbeat-timeout`: при конкретном значении
базы перевыборов потолок пульса равен reelection-timeout/10. При
умолчании узла 430 мс потолок равен 43 мс; при стендовом значении
500 мс — 50 мс (стендовому пульсу 45 мс остаётся запас 5 мс).
Независимо от этого действует верхняя граница диапазона 100 мс.

## Флаги генератора нагрузки loadkv

Генератор `loadkv` принимает 10 флагов.
Проверка на этапе запуска есть только у `-request-rate`;
согласование долей операций описано в подразделе «Семантика долей».

| Флаг                | Умолчание      | Единица                | Границы                                     |
|---------------------|----------------|------------------------|---------------------------------------------|
| `-concurrency`      | 4              | запросы                | —                                           |
| `-delete-percent`   | 0              | %                      | лестница долей                              |
| `-duration`         | 0 = до сигнала | duration               | —                                           |
| `-get-percent`      | 66             | %                      | лестница долей                              |
| `-key-count`        | 2000           | ключи                  | —                                           |
| `-peers`            | «»             | `host:port,...` (HTTP) | —                                           |
| `-request-rate`     | 100            | 1/с                    | ≥ 1, иначе отказ (cmd/load/main.go)         |
| `-value-size`       | 128            | байты                  | —                                           |
| `-verify-percent`   | 33             | %                      | —                                           |
| `-weak-get-percent` | 0              | %                      | лестница долей                              |

- `-concurrency` — предельное число одновременно выполняемых запросов.
- `-duration` — длительность прогона; ноль означает работу до сигнала
  остановки (прерывание с клавиатуры или SIGTERM).
- `-key-count` — число различных ключей, из которых выбирается ключ
  каждой операции.
- `-peers` — адреса узлов кластера через запятую; допускается префикс
  `http://`, при отсутствии схемы адрес трактуется как HTTP-адрес.
  Пометка «(HTTP)» в столбце единицы — указание протокола адресов
  генератора, а не описание HTTP-интерфейса (он описывается отдельным
  документом).
- `-request-rate` — темп старта запросов; значение меньше 1 отвергается
  при запуске с сообщением `invalid -request-rate: must be >= 1`.
- `-value-size` — размер значения в байтах для операций записи.
- `-verify-percent` — доля операций записи и удаления, после которых
  ключ перечитывается (см. ниже).

### Семантика долей

Вид операции выбирается «лестницей долей»: для случайного числа r из [0; 100)
проверяются полосы:

- [0, d) — DELETE, где d = delete-percent;
- [d, d+w) — слабое чтение, где w = weak-get-percent;
- [d+w, d+w+g) — GET, где g = get-percent;
- остаток [d+w+g; 100) — PUT.

При сумме долей больше 100 усекается последняя достигнутая полоса (при
d > 100 — DELETE, при d+w > 100 — слабое чтение, иначе GET), все
последующие полосы и PUT пусты. Значения долей вне [0; 100] не
поддерживаются: отрицательная доля сдвигает все последующие границы
вниз.

`-verify-percent` не участвует в лестнице: после успешной записи (и
после успешного удаления) с вероятностью verify-percent ключ
перечитывается слабым чтением для сверки результата.

## Связь с переменными Makefile

Переменные стенда передаются флагам целью`start-raft` 
и переопределяются командной строкой make без правки файла.
Временные параметры узлов задаются числом миллисекунд 
— суффикс `ms` подставляет рецепт цели.

| Переменная             | Флаг                                      | Умолчание Makefile |
|------------------------|-------------------------------------------|--------------------|
| `APPLY_BATCH_INTERVAL` | `-apply-batch-interval`                   | 50                 |
| `HEARTBEAT_TIMEOUT`    | `-heartbeat-timeout`                      | 45                 |
| `REELECTION_TIMEOUT`   | `-reelection-timeout`                     | 500                |
| `TICKER_TIMEOUT`       | `-ticker-timeout`                         | 20                 |
| `TRACE_LOG_LEVEL`      | `-trace-log-level`                        | 0                  |
| `CONCURRENCY`          | `-concurrency`                            | 8                  |
| `DELETE_PERCENT`       | `-delete-percent`                         | 0                  |
| `DURATION`             | `-duration`                               | 5m                 |
| `GET_PERCENT`          | `-get-percent`                            | 75                 |
| `REQUEST_RATE`         | `-request-rate`                           | 200                |
| `VALUE_SIZE`           | `-value-size`                             | 128                |
| `VERIFY_PERCENT`       | `-verify-percent`                         | 33                 |
| `WEAK_GET_PERCENT`     | `-weak-get-percent`                       | 0                  |
| `STAND`                | — (префикс имён файлов артефактов стенда) | пусто              |

Стендовые умолчания остальных флагов генератора отличаются от
умолчаний бинарника: `CONCURRENCY` 8 против 4, `GET_PERCENT` 75
против 66, `REQUEST_RATE` 200 против 100. Флаг `-key-count` цели
`start-raft` не передаётся — действует умолчание бинарника.
